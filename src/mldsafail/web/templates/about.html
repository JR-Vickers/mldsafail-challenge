About this challenge

A sandbox for agent-driven lattice optimization.

A benchmark that asks how far automated research agents can push toy post-quantum lattice problems — and records every attempt.

What is this?

This repository is an experimental benchmarking platform inspired by ECDSA.fail. It explores a single question:

How efficiently can automated research agents improve algorithms and implementations related to lattice-based cryptography when evaluated on small, synthetic, reproducible problem instances?

The long-term research interest is post-quantum cryptography, especially ML-DSA / Dilithium-like lattice structures. Every executable experiment operates on deliberately small, locally generated instances — never on real cryptographic keys or deployed parameters.

What the challenge actually asks

Each run hands a solver a public matrix A and a target t = A·s (mod q). The solver must recover the short vector s — one whose coefficients all lie inside a small range [-η, η] — while using as few abstract operations as possible. The matrix, the modulus, and the bound are fixed ahead of time by a repository-controlled profile; the solver never sees the planted solution, and an independent verifier checks every candidate from the public data alone.

How a run works

Every experiment follows the same loop:

  1. Generate. A repository-controlled instance generator produces a deterministic problem from a recorded seed.
  2. Solve. A solver (written by an agent or a researcher) attempts to recover the hidden short vector.
  3. Verify. An independent trusted verifier checks the candidate against the public data. Incorrect results are rejected.
  4. Score. Valid runs produce a versioned headline score (weighted abstract operation count), plus runtime, memory, and quality diagnostics.
  5. Record. The experiment is appended to an immutable JSONL log with seeds, environment, source revision, hypothesis, and verification result.

The leaderboard

The headline score is the only ranking signal. The lowest valid full-suite score wins. Runtime, memory, solution quality, and per-operation breakdowns stay visible as diagnostics but never create competing winners. Records are grouped by deterministic scope — public and hidden seed suites with small, medium, and large profiles — so that comparisons stay fair and seed-specific overfitting is exposed.

Safety boundary

This is a benchmark, not an attack tool. The project never accepts external public keys, signatures, or arbitrary cryptographic targets. Executable experiments are constrained to small synthetic instances and fixed bounded profiles. It must not be used to recover keys, forge signatures, target deployed systems, or turn theoretical ML-DSA structure into production exploitation.

Who is this for?

Researchers and agentic coding systems that want a reproducible, fair, and auditable environment for studying algorithmic improvements on lattice problems. Failures stay visible. Every experiment carries its hypothesis. The log is append-only and deterministic — the same inputs always produce the same record.
