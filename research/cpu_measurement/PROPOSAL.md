# Host CPU accounting proposal — inactive

The harness reads `cpu.stat usage_usec` from a dedicated persistent cgroup v2
parent, before worker creation and after container removal and descendant exit.
It never reads contestant timing fields. The owner must provision the delegated
parent and matching Docker `--cgroup-parent` identity. Keep the parent until the
final measurement and evidence are saved. A populated domain, missing counter,
regression, Docker cleanup failure or surviving descendant fails closed.

The kernel documents hierarchical accounting and inherited process membership:
https://docs.kernel.org/admin-guide/cgroup-v2.html
The trusted host, kernel, Docker daemon, cgroup delegation and verifier are inside
the trust boundary. Contestant processes, clocks, candidates and timing fields
are outside it. No cgroup mount or host socket is exposed to the worker.
The library snapshots source through the existing approved Python-only 2 MB
source validator before invocation. It proves worker membership from host /proc
before supplying stdin; mismatched accounting domains fail closed. Public input must be generated by the
existing fixed tiny profiles and the caller must supply the independent verifier.
This is a library prototype, not an alternative submission endpoint.

This measures the whole worker lifetime, including interpreter startup, imports,
parsing and serialization. It is incompatible with the frozen 0.5.0 timing
convention. Adoption would require a separately reviewed benchmark (proposed
0.6.0), rebuilt reviewed worker, fresh per-host reference epoch, separate cohorts,
and new ranking records. Preserve all 0.5.0 scores and artifacts; no conversion.

## Native feasibility and repeatability gate

Local host is macOS ARM64; native rootless Linux cgroup tests are **pending**.
No native feasibility or overhead result is claimed. Docker Desktop is not a
substitute. On the actual VPS, record kernel, Docker API/cgroup driver, delegated
parent and worker IDs privately; publish only sanitized identities and aggregates.
Prove Docker places every worker below the parent and that its CPU remains
accounted after removing the child cgroup, including grandchildren.

Run at least 30 paired empty-worker and deterministic CPU fixtures sequentially
on an idle host. Record whole-worker CPU, wall time, parent counter before/after,
verified candidate disposition, overhead medians/p95 and coefficient of variation.
Declare acceptable overhead and repeatability thresholds before execution.
Test: clock monkeypatching, forged CPU fields, child/grandchild computation,
early exit, malformed JSON, timeout with surviving children, oversized streams,
counter deletion/read failure, incorrect parent mapping and counter regression.
The first two must not change authoritative CPU; children must increase it;
missing accounting must prevent an experimental score. Unit tests establish only
counter collection behavior, not native lifecycle integrity. Owner review remains
required before adoption.

Run the prepared fixtures with `python -m research.cpu_measurement.native_suite --help`.
The suite includes 30 empty/child repetitions and tampering/exit/malformed/timeout
fixtures. Counter/membership failures have local tests. Native fixture results
remain pending.
