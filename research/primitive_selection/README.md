# Primitive-selection study

This package compares reduced-scale MLWE recovery, Module-SIS relation search,
and basis reduction as a shared kernel. It is isolated from the production web
application and accepts no external instance files or arbitrary parameters.

Research v2 pairs `(n,q,k/l)` as `(4,97,2/1)`, `(8,97,2/2)`, and
`(16,193,3/2)`, with eta 1 and 2. Small, medium, and large/eta=1 are proposed
MLWE challenge cells; large/eta=2 is a stress cell. Module-SIS is retained as a disqualified
comparator after direct modular recovery of its planted construction. The
original v1 cohort and source are preserved separately. No primitive is selected
until review and held-out validation pass.

Public solver objects contain no generation seeds or evaluator witnesses.
Generation streams separate version, track, profile, eta, seed, and purpose.
The exact proposed contract and migration requirements are in
[the specification](../../docs/PRIMITIVE_SELECTION_SPEC.md).

Run through the pinned dependency container:

```sh
research/primitive_selection/primitive-study smoke
research/primitive_selection/primitive-study run --cohort development
research/primitive_selection/primitive-study verify-results --input /study/research/primitive_selection/results/RUN/development.jsonl
research/primitive_selection/primitive-study report --input /study/research/primitive_selection/results/RUN/development.jsonl
```

Validation must happen only after code/configuration freeze with a fresh nonce
generated by the agent conducting the specialist review. External human review
is optional; follow the evidence and approval procedure in
[`docs/PRIMITIVE_SELECTION_REVIEW.md`](../../docs/PRIMITIVE_SELECTION_REVIEW.md).
The nonce is embedded in every validation
record. Validation additionally requires --freeze and --nonce-record paths in
the container, and an image rebuilt at the referenced freeze commit. Each case
receives one warm-up and three measured repetitions in a
fresh subprocess, with one CPU, a 60-second wall deadline, and a 2-GiB address
space/container limit. The parent randomizes solver order and reports median
process CPU time; Benchmark 0.4.0's cooperative operation meter is not used.

The container pins its base image by digest and installs exact solver and test
dependencies. Every result stores the built image content digest. The expanded
portfolio has 960 development and 1,920 validation records, including the
original portfolio's 780/1,560 subset and three added simple comparators.

Every invocation creates a unique manifest and refuses to overwrite evidence.
Interrupted JSONL remains partial and cannot enter final analysis. Audit
regenerates inputs, independently verifies stored candidates and quality, and
checks the entire expected grid, provenance, settings, digests, and aggregates.
Reports distinguish all outcomes and use seed-level uncertainty. The historical
REPORT.md remains unchanged; new default reports use REPORT-AUDITED.md.

After starting Docker, `research/primitive_selection/rebuild-check.sh ABSOLUTE_NEW_OUTPUT_DIRECTORY` performs
two clean image builds and compares deterministic fixture IDs and normalized
smoke outputs. Timing and host metadata are intentionally excluded from that
comparison. Both clean-build outputs and audit evidence are retained. Run the
focused tests inside an image with `docker run --rm --entrypoint python IMAGE
-m pytest tests`; run the repository completion check with `make check`.
