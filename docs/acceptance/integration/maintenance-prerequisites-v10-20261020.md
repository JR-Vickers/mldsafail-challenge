## Engineering advanced

The investigation Docker router admits the actual frozen evaluator command
shapes: image inspection, artifact inspection, daemon information, worker run,
kill, state inspection and removal. It injects operation ownership and common
cgroup placement, persists create/start/birth intent, rejects unowned resources,
concurrent unsettled workers and solver mounts outside the generation, and avoids
resurrecting a removed journal after timeout cleanup. It supports both approved
Docker image-ID representations by binding the inspected index/configuration
identity before downstream commands. The controller wrapper uses the frozen
image's actual `/usr/local/bin/docker` binary.

The runner continuously checks its guard while a phase is running. A host monitor
samples every 250 ms, captures phase boundaries, bounds callback and file I/O,
and retains ambiguous reader/writer state after a deadline. Sampling covers
setup, create/reference, audit and cleanup. Gzip preserves raw JSON rows while
bounding stored sampling evidence to 64 MiB; replay bounds decompression too.
The combined operation log ceiling remains 128 MiB and the entire generation,
including the separate epoch destination, remains bounded to 1 GiB. Both output
filesystems must retain at least 2 GiB free.

Raw validation requires the same operation identity and a completed single-attempt
record. It rechecks phase coverage, timestamps, scope separation, process/cgroup
identities, all ancestor paths/limits, counters, swap and emergency floors. Shared
host constraints are distinguished from disjoint scope limits. An arbitrary
compatibility string cannot certify capacity: assessment requires actual
hash-bound retained evidence and complete same-host observations. Isolated-host
availability cannot stand in for production availability; cross-host sizing stays
unresolved pending the protocol's compatibility review and actual evidence.

The native adapter checks the approved host boot/daemon/image identities,
configured parent limits, a separate generation-owned control leaf, controller
commands/mounts and audit socket exclusion, worker resource limits, concurrency,
retained-service health and output limits. The monitor process belongs in the
control leaf; placing it in the common parent would violate cgroup v2's
no-internal-process rule. Cleanup terminates controllers first, then exact owned
workers/clients. Crash cleanup uses durable container births and the inspected
control leaf to prove orphaned clients stopped; it never resumes execution.

The SQL adapter binds the database/container/daemon/source/connection authority,
checks helper namespace, mounts, resource limits and births, keeps holder and
verification connections separate, and delivers credentials only on private
bounded input. Helper journals retain cumulative cleanup authority. Cleanup-only
reconstruction attempts every recorded helper and cannot treat a missing client
birth or lost creation acknowledgement as success. The supervisor enforces
action deadlines, preserves the epoch API's context when invoking actions, latches
fence failure before cleanup, monitors restart interference, and refuses restoration
while an action remains alive. Restoration attempts retain an ambiguous status
until positively verified. Concrete production action adapters retain all existing
privileged-receipt, capacity, scheduling and epoch authorization gates.

Static source closure now follows repository imports without importing their
code, identifies locked external/runtime requirements, and records dynamic review
sites. Explicit bundle mappings preserve receipt bytes and relative dependencies;
relocation validation checks their actual targets and hashes. A successful static
mapping never automatically claims complete runtime or semantic closure.

## Remaining gates

Native end-to-end acceptance needs an approved compatible host with the frozen
images and inspected operation/control/client delegation. The owner must bind
host identity, provider selection and execution window before generated execution
commands can become reviewable for execution. The agent cannot invent those
identities or provision a host under preparation-only authority.

Owner-only paths and unresolved scheduling/configuration/import semantics still
need evidence and semantic review before a complete external-path allowlist or
another owner-console collection. Existing app/session delegation is evidence of
structure, not an approved installed operation delegation. Full runtime and
relative production-receipt closure stays false where retained inputs are absent
or require separately approved transfer. Actual retained-service/timer/ancestor
measurements and isolated-to-production compatibility cannot be manufactured from
local control tests.

Consequently there is no capacity execution request yet. Delegation provisioning,
maintenance/transfer, capacity investigation and `production_epoch_only` remain
different approval purposes. Preparation freshness stays 24 hours; execution
inspection freshness stays five minutes. Keep zero-pending semantics, current
timers, web/database/proxy, supplied secrets and accepted provenance. 0.5.0 stays
the preview, 0.6.0 ignored, C diagnostics abandoned and backups deferred.

The reviewed packet now binds exact configuration bytes before parsing for both
execution and cleanup. Changing the Docker endpoint, operation/control scopes,
retained services, runtime versions or sample identities invalidates that binding.
The fence also prunes completed verification-thread objects while preserving
unresolved readers; an 8,000-second window no longer accumulates dead Thread
objects. Release snapshots that registry under its lock. Diagnostic guard bytes
and zero-pending lock semantics remain unchanged.
