# Bounded in-container profile

Run once: control, then profile, using the exact retained generation-D image and
empty fixture on public tiny `small/seed0/eta1` data. Hypothesis: Python adapter
execution or its imports explain the CPU growth observed after Python exec.
The profile overrides only the entrypoint with Python import timing and cProfile
around the unchanged worker module. It is instrumentation, not a correction.

Use `scripts.native_worker_profile.py` through the existing source-bound owned
native driver and delegated operator wrapper. Bind callback, aggregate helpers,
clean source, reviewed image/archive and independent review packet. Check current
historical ownership domains/sockets and protected container identities before
provisioning. Serialize against evaluations, maintenance and other diagnostics.
The fresh disposable root must have a short socket path.

Both invocations retain the existing network/filesystem/UID/capability/CPU/memory/
PID sandbox restrictions; the profile executes the unchanged worker limits and
fixed solver. Each start has a 60-second command bound; the wrapper command bound
is 900 seconds with a 1,200-second systemd outer runtime limit. There is no
evaluation or score here. The diagnostic uses a different stdin/attach sequence
from the measurement harness. Its cgroup totals, wall times and instrumented
function times are explanatory and cannot pass measurement acceptance, establish
speedup, replace official counter windows or change any existing score.

Stop on first failure; retain output and journals. Do not rerun unchanged samples.
On command failure, the command helper cancels its exact CLI domain. Final driver
ownership cleanup requires the positive whole-daemon/worker barrier before its
remaining uncertain client cancellation. Independently inspect driver, daemon/worker/operator cgroups, sockets,
client birth identities and unchanged protected container identities after exit.
Only then publish a sanitized receipt. Raw streams and source/image archives stay
private. No live staging changes, adoption, defaults or production activation.
