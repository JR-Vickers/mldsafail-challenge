# Actual SSH transport-loss recovery protocol

Use a NEW owned QEMU overlay and copied firmware state only. Reuse the protected original Ubuntu disk solely as immutable backing after quiescence and hash checks. Expose only loopback SSH; import the previously verified official PostgreSQL image archive offline. No shared VPS, private staging evidence, benchmarks, or owner credentials participate.

The source-reviewed native driver runs in a delegated persistent user unit. Its configuration, full source/image/archive/helper identities, unit name, and owner intent are durable before invocation. Launch a gated, identity-recorded host SSH client running `systemd-run --user --wait`; the callback creates a tiny network-isolated fixture and durably records its boot ID, owner PID, container ID and daemon epoch before waiting.

After observing that healthy boundary while SSH remains live, durably record drop intent and terminate that exact owned SSH client, proving native return code -9. Do not signal the guest owner. Reconnect over a NEW actual SSH connection; require unchanged guest boot ID and exact still-running owner unit MainPID. Publish a private atomic fsynced acknowledgement. The existing owner checks those identities, verifies exact public fixture data, runs independently retryable cleanup twice, and exits. Require unit success, strict callback success, complete outer driver cleanup, and whole-daemon/worker barrier evidence. Never resubmit the interrupted operation.

Preserve failed and partial results. Host finalization independently collects private evidence, cancels any owned transport client, stops owned QEMU, and verifies original hashes. Any execution, collection, cleanup, or publication failure leaves overall false. Actual transport loss is distinct from the earlier hard-power-loss gate: this protocol requires the boot ID to remain unchanged. It establishes synthetic operational recovery only; no off-host custody, production activation, private epoch restoration or benchmark acceptance is claimed.
