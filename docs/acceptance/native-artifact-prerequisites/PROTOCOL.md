# Native reproduction artifact prerequisites

Run `uv run --extra dev python -m scripts.native_reproduction_artifacts --config PRIVATE_CONFIG` inside the actual delegated owned operator unit. Use the generic native driver configuration, `daemon_kind=owned`, and this callback's exact `acceptance_source_sha256`. The operator source must be a clean retained commit. This callback builds and exports artifacts only; it runs no cases, epochs, scores, or adoption operation. Driver whole-daemon/worker/client cleanup must independently pass.

Beside `state_root`, retain `v060-worker-protocol.json` using the already reviewed approved offline AMD64 wheel protocol. Retain `reproduction-artifacts-protocol.json` with exactly `schema: mldsafail.reproduction-artifacts-protocol.v1` and `source_review: PRIVATE_REVIEW_PATH`. The review object requires schema `mldsafail.native-artifact-source-review.v1`, `passed: true`, exact operator `source_commit`, `primitive_source_files_sha256` equal to `scripts.native_reproduction_artifacts.source_files(repository)`, a named independent reviewer and nonempty evidence references. This source review is distinct from native scientific acceptance.

The callback pulls the frozen digest-pinned official Python 3.12.10 AMD64 base, retains its actual registry inspection and exports `python-base.tar`. It builds the unchanged scientific Python/schema/test files with the original dependency versions, approved offline cysignals/fpylll wheels, and explicitly pinned native GMP/MPFR packages. The copied scientific Dockerfile and requirements remain unchanged; the separate assembly Dockerfile records the substitutions. It exports `primitive-study.tar` and retains full context file hashes.

Under the private journal parent, `reproduction-artifacts/` contains the two sealed archives, `python-base-provenance.json`, `primitive-study-provenance.json`, and `study-context.json`. For the baseline/reproduction acceptance callback, configure `base_image`, `base_provenance`, `frozen_image`, and `frozen_provenance` from these receipts. Import each exact archive SHA through the next generic driver configuration's primary/additional images. Retain the same approved wheel inventory. The consumer rechecks source hashes, immutable image identity, original registry mapping and loaded archive provenance before scientific acceptance.

A build/export receipt does not prove reproduction, measurement, public launch, default activation, or production adoption. Native execution and final outer cleanup remain required and all raw receipts stay private.
