# Sealed protected local restoration

This gate restores the entire protected database and independently audits its frozen 0.5.0 epoch and every accepted result's private evidence. It does not require off-host storage credentials and does not establish off-host durability, recovery-password custody, production activation, or old Docker container identity preservation.

Run `scripts.native_protected_local_restoration.callback` through the reviewed generic owned native driver, with a fresh dedicated rootless daemon, exact loaded PostgreSQL image as `config.image`, and retained frozen coordinator image loaded as an additional approved archive. Never run against the default staging Docker endpoint. The driver supplies the current private daemon manifest and operator cgroup authority; its terminal barrier must pass independently.

Before execution create a private protocol file referenced by `config.acceptance_protocol` containing exactly `schema` (`mldsafail.local-protected-restore-protocol.v1`), `recovery_set` (protected sealed local directory), `manifest_sha256`, `epoch_id`, `result_count` (at least one actual accepted result), and `coordinator_image` (full immutable SHA256 image ID). Retain the exact source/review/image/archive identities and protocol privately. The recovery set must contain all seven manifest categories with intact hashes; its secrets and private epoch must remain protected.

Acceptance requires immutable snapshot restoration in a new network-isolated database, equality of all SQL schema/data statements with the sealed custom archive, frozen evaluator audit of epoch/reference material and all accepted run evidence, exact expected epoch/result inventory, independently repeatable cleanup and a successful outer driver barrier. Generated dump comments/nonces are normalized only outside COPY payload; private row contents remain exact. No migrations run. Failed or partial receipts stay retained and cannot count as a pass. Local receipts never update the off-host backup freshness state.
