# Versioned distribution handoff

This is preparatory operator material. `deploy/templates/participant-v060-release.json`
is an incomplete, unapproved identity packet, not an adopted contract or a release
manifest accepted by frozen 0.5.0 tooling. Null fields remain pending until their
exact source-bound evidence exists. Never substitute timestamps, tags, simulated
runs, owner silence or 0.5.0 results for these references.

The retained 0.5.1 participant wheel implements benchmark 0.5.0. Its separately
recorded wheel source identity must remain distinct from archive/documentation
source identity, even when unchanged wheel bytes are reused. The included frozen
specification is a presentation copy: record original and included hashes, and
verify that removing repository-local links leaves scientific prose unchanged.
Retain earlier candidate archives and review failures.

For a prospective 0.6.0 distribution:

1. Wait for native supervisor/accounting gates, independent supervisor and auditor
   signoff, owner contract adoption, and reviewed explicit version/cohort
   integration. Freeze the exact accepted source. Do not assign a package version
   or claim an approved production default before the relevant decision.
2. Build distinct participant and worker artifacts; record their source commits,
   locks, architecture and checksums. Prepare an isolated 0.6.0 epoch and audited
   reference costs. Reusing or converting 0.5.0 costs or results is prohibited.
3. Create a self-contained allowlisted public archive with the adopted contract,
   matching starter, version-specific install/development/scoring/submission and
   cancellation documentation, checksums and public generated fixtures. Extend
   archive and retained-release tooling separately with reviewed version support;
   the current 0.5.1 archive builder must reject/avoid relabeling 0.6.0 artifacts.
4. Independently inspect the actual archive, including wheel inventory, path/link
   safety, secret/evidence exclusions, byte-matched starter, all local links and
   separate wheel/documentation provenance. Install into a new environment on each
   declared supported platform. Preserve failed installations. Use the exact
   retained worker image for public fixture correctness reproduction; cross-host
   timing equality is not a release promise.
5. Verify API/CLI selection, independent audit handling, disjoint leaderboard
   cohorts and an approved-design fresh-epoch production rehearsal. A frozen
   0.5.0 baseline rehearsal cannot satisfy this gate. Populate the packet with
   evidence references without embedding raw private evidence or infrastructure
   locations.
6. Submit exact identities and unresolved gates to the owner. Publication,
   production/default activation and recruitment are separate decisions. Prepare
   commands and checked artifacts before requesting those decisions; send no
   invitations and upload/publish nothing without authorization.

Participant-facing score text must state exactly three measured invocations,
whole-case ordinary-failure penalties, independent correctness verification and
infrastructure-failure treatment for invalid accounting or incomplete cleanup,
using the adopted contract's unchanged thresholds. Describe private audited
cohorts without exposing private seeds, nonce, witnesses, candidates or raw host
accounting. Clarify that local public development is diagnostic and historical
`make bench`/`mldsafail run` still measure 0.4.0 until separately changed and reviewed.

The final reproduction handoff includes immutable source/image/hash identities,
installation platform, fixture/source identities, normalized correctness,
independent audit outcome, cleanup receipt and known limitations. Keep raw
operator logs protected; commit only sanitized references. No pending field is a
passed gate.
